# Безопасность Lovelab

Проверено 23 сентября 2026 года. Здесь описаны реализованные меры, тесты и оставшиеся ограничения. Аудит не гарантирует отсутствия всех возможных уязвимостей.

## Доступ и данные

- **Гость** видит опубликованные задачи, команды и открытые отклики. Читать чужие черновики и выполнять действия он не может.
- **Бизнес** создаёт задачи, редактирует и публикует только свои карточки. Только владелец задачи выбирает команды и подтверждает этапы.
- **Команда** отправляет отклики только от своей команды и редактирует только собственный профиль. Роль выбирается при регистрации и не меняется запросом редактирования профиля.
- Сервер проверяет права для каждого действия. Скрытие кнопок в интерфейсе — дополнительная мера удобства.
- Начальные записи без владельца остаются демонстрационными и не назначаются первому зарегистрированному человеку.

Опубликованные карточки, включая указанные в них контакты, видны всем. Публикуйте только сведения, которыми готовы поделиться. Сессия не хранится в `localStorage`; сохранённый ввод конструктора разделён по аккаунтам на устройстве.

## Защита

Пароли обрабатываются `scrypt` с отдельной случайной солью для каждой записи (`N=2^17`, `r=8`, `p=1`). Сравнение хешей выполняется за постоянное время. Параметры соответствуют [рекомендациям OWASP по хранению паролей](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).

Сессия — случайный токен 256 бит; в SQLite хранится только его SHA-256. Cookie имеет `HttpOnly`, `SameSite=Lax`, `Path=/`, срок 8 часов и `Secure` при HTTPS. Вход создаёт новый токен, выход удаляет серверную сессию. Приватные ответы не кешируются. О принципах: [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

Межсайтовые изменяющие запросы отклоняются по `Origin` и `Sec-Fetch-Site`. Тело запроса ограничено 128 КиБ, включая потоковую передачу. Ограничены размеры полей и числовые идентификаторы. Вход и регистрация ограничивают частоту запросов; одновременно выполняется не более двух операций хеширования паролей и двух запросов генерации вопросов в процессе.

SQL использует параметры; динамические имена полей берутся из закрытых списков. Пользовательский текст выводится средствами React, без вставки HTML. Внешние ссылки допускают HTTP(S); переходы открываются с `noopener noreferrer`. CSP для приложения запрещает внешние скрипты и встраивание страницы, включены `nosniff` и `no-referrer`.

Сервер генерации не принимает адрес назначения от пользователя. Перенаправления провайдера запрещены, чтобы не передавать ключ на другой адрес; ответ ограничен 64 КиБ и проверяется по структуре. Прототипы сервер не скачивает. Повторное подтверждение этапа защищено транзакцией SQLite и не начисляет баллы повторно.

## Результаты аудита

Проверены запросы SQL, права владельцев и ролей, изменение идентификаторов чужих объектов, поддельные/просроченные сессии, выход, фиксация сессии, CSRF, XSS, некорректные URL, большие запросы, обход статических путей, конкурентные начисления и потери введённых данных при задержках сети.

- `npm audit` в корне, `frontend/` и `task_builder/frontend/`: известных уязвимостей не найдено.
- `pip-audit` для точных установленных версий `.venv`: известных уязвимостей не найдено.
- В отслеживаемых файлах и истории не найдены `.env`, базы, приватные ключи или совпадения известных шаблонов секретных токенов. Проверка шаблонами не доказывает отсутствие любых секретов.

В requirements используются диапазоны версий: повторите аудит после установки зависимостей.

## Ограничения перед промышленным запуском

Почта пока не подтверждается письмом; восстановления пароля, MFA и проверки организации нет. Не представляйте аккаунт как подтверждённую личность или компанию. Нет защиты от распределённой массовой регистрации и квот хранения; ограничения частоты и параллелизма действуют в одном процессе и сбрасываются при перезапуске. Для масштабирования нужны общий ограничитель, мониторинг и журнал действий. Нагрузочное тестирование публичного сервера не проводилось.

Для входа из интернета необходим HTTPS. HTTP на localhost поддерживается для разработки; публичный туннель предоставляет HTTPS, пока работает компьютер. Нельзя доверять произвольным заголовкам прокси: Uvicorn должен принимать их только от известного локального туннеля или обратного прокси.

Корректный адрес прототипа не гарантирует безопасность или доступность внешнего сайта. Приложение не сканирует его содержимое.

## Как повторить проверки

```bash
python -m unittest discover -v
npm run test:e2e
npm audit
npm audit --prefix frontend
npm audit --prefix task_builder/frontend
# Python из проверяемого .venv
python -m pip install pip-audit
python -m pip_audit
```

Серверные и браузерные тесты используют временные базы, не рабочую `backend/app.db`.
