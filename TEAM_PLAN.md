# План команды: кейс по геймификации задач

Источник: [задание HackAlem AI](https://docs.google.com/document/d/1lFWekP2SirFarATKkWa5neHNL5DlhjZKkUacvGyZk8k/edit?tab=t.0).

## Цель MVP

За 5 часов показать работающий путь: черновик бизнес-задачи -> минимум 3 уточняющих вопроса -> редактируемая и подтвержденная карточка -> рейтинг -> публикация в каталоге -> отклик команды -> ручное решение бизнеса. После подтверждения фактического этапа выбранная команда получает баллы. Низкий рейтинг не скрывает опубликованную задачу и не запрещает отклики.

## Стек и общие правила

- Интерфейс: React, TypeScript, Vite. API: FastAPI, SQLite из стандартной библиотеки Python.
- Ключ внешнего AI API хранится только на сервере. Если API недоступен, используется локальная заглушка с показанными промптом, форматом входа/выхода и обработкой некорректного ответа.
- Не добавлять регистрацию, чат, уведомления, файловое хранилище и автоматическое назначение команды.
- Каждый участник работает в своей ветке, делает собственные коммиты и пушит ветку. Слияние в `main` через PR после проверки соответствующего сценария.
- Перед работой каждый ИИ читает этот план и берет только назначенную область. Изменения общего контракта обсуждаются с командой до правки; важные решения фиксируются здесь или в PR. Ветки не синхронизируются автоматически: перед интеграцией нужно обновить их от `main`.

## Общий контракт

До параллельной реализации согласовать названия полей и ответов API. Базовый контракт:

- `Task`: `id`, `title`, `topic`, `context`, `need`, `users`, `data`, `constraints`, `expected_result`, `success_criteria`, `contact`, `interaction_format`, `status` (`draft`/`published`), `score`. Рейтинг вычисляется из подтвержденных полей, а не вводится вручную.
- `Team`: `id`, `name`, `interests`, `skills`, `technologies`, `points`.
- `Proposal`: `id`, `task_id`, `team_id`, `idea`, `plan`, `duration`, `prototype_url`, `decision` (`pending`/`selected`/`rejected`), `progress_confirmed`.
- Выбор нескольких команд допустим; отсутствие выбранной команды тоже допустимо. В MVP у выбранного отклика один подтверждаемый этап: после ручного подтверждения прогресса бизнесом команда получает 10 баллов один раз. Рейтинг задачи от 0 до 100 не меняется.

### Участник 1: конструктор и AI

- Бизнес вводит свободное описание; AI задает не менее трех уместных вопросов и не добавляет факты от себя.
- Ответы превращаются в карточку со всеми обязательными полями; бизнес может изменить и подтвердить ее до публикации.
- Некорректный ответ AI обрабатывается явно; секретный ключ не попадает в браузер или репозиторий.
- В PR показан переход от слабого описания к опубликованной карточке.

### Участник 2: рейтинг и каталог

- Вес полей по ТЗ: контекст и потребность 20, данные 20, результат 15, критерии успеха 15, ограничения 10, пользователи 10, связь с бизнесом 10. Максимум 100.
- Показываются начисленные баллы, недостающие сведения и уровень: 0-39 черновик, 40-69 рабочая, 70-89 готовая, 90-100 приоритетная. После подтвержденного изменения рейтинг пересчитывается.
- Все опубликованные задачи видны, включая задачи с низким рейтингом; доступны сортировка по баллам и фильтры по теме/уровню.
- Подготовлены минимум 5 синтетических черновиков и 5 карточек с разной полнотой.

### Участник 3: отклики и решение бизнеса

- Любая команда может подать предложение: идея, план, срок и ссылка на прототип. Число откликов не ограничено.
- Бизнес видит и сравнивает предложения, вручную выбирает одну или несколько команд либо не выбирает никого; отклонение доступно отдельно.
- После подтвержденного этапа выбранная команда получает 10 баллов; повторное подтверждение не удваивает баллы.
- Подготовлены минимум 5 профилей команд и 5 примерных откликов; README содержит запуск и шаги демо.

## Интеграция и время

1. 0-30 мин: согласовать контракт, создать каркас приложения. Участник 2 первым добавляет общую схему и хранилище в небольшой PR; остальные начинают свои отдельные модули по контракту.
2. 30-180 мин: три участника реализуют свои сценарии и пушат промежуточные коммиты в собственные ветки. Общие файлы меняет их владелец; нужные изменения обсуждаются в PR.
3. 180-225 мин: объединить PR, связать экраны и API, пройти путь от черновика до решения бизнеса.
4. 225-270 мин: проверить рейтинг, низкорейтинговые задачи, несколько откликов, некорректный AI-ответ и подтверждение прогресса; исправить блокирующие ошибки.
5. 270-300 мин: подготовить запуск по README и демонстрацию до 5 минут на одном примере.

Готово, когда весь обязательный сценарий работает в приложении, каждый участник запушил свои коммиты, а README объясняет архитектуру, формулу рейтинга, правила каталога и демо-сценарий.
